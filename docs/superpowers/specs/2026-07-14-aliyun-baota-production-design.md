# 阿里云宝塔生产部署收口设计

日期：2026-07-14

目标服务器：`121.196.161.249`

主站域名：`mc-u.top`

保护范围：保持 `star-web.top` 现有站点内容和配置不变

## 1. 目标

将当前“进程部分在线、宝塔配置未收口”的状态整理为可维护的生产部署：

- `mc-u.top` 提供完整千服前端和 API。
- HTTP 强制跳转 HTTPS，证书链受浏览器信任。
- Node API、MySQL、Redis 等内部服务不直接暴露公网。
- Nginx、数据库、缓存和 PM2 的启动方式与宝塔管理边界一致。
- 部署、备份、健康检查和回滚路径可重复执行。
- 支付域先准备配置，DNS 未切换前不激活。

## 2. 当前基线

只读审计确认：

- 宝塔面板和任务进程在线，面板端口为 `27438`。
- Nginx 配置语法有效，实际进程监听 `80/443`，但 `nginx.service` 状态为 `failed`。
- `mc-u.top` Nginx 根目录为 `/www/wwwroot/mc-u.top`，公网返回 917 字节的宝塔占位页。
- 千服前端产物位于 `/www/wwwroot/mc-u.top/dist`，尚未作为站点根目录。
- `qianfu-api` 由 PM2 运行，脚本为 `/www/wwwroot/qianfu-app/dist-server/server/index.js`，公网健康检查正常。
- `mc-u.top` 使用自签名证书，标准 TLS 校验失败。
- MySQL 和 Redis 进程存在，但 systemd 状态不能反映其真实运行状态。
- 公网可连接 `3001`、`3306`、`3452`、`8787`、`8788` 和 `27438`。
- 服务器内存约 3.5 GiB，无 Swap。
- `pay.star-web.top` 仍解析到旧地址 `103.71.69.43`。

## 3. 方案选择

采用分阶段原地收口，不重装系统，不容器化迁移。

原因：现有 API 和其他站点已经运行，原地收口可保留数据与业务连续性，并为每一步设置独立回滚点。只修前端和证书会继续留下公网端口、启动管理与备份风险；整机重建的变更面和停机风险则明显过大。

## 4. 目标架构

```text
Internet
  |
  +-- 80/443 -> Baota Nginx
                   |
                   +-- /, static -> qianfu frontend dist
                   +-- /api/, /auth/ -> 127.0.0.1:3001

Local services only
  +-- qianfu-api -> 127.0.0.1:3001
  +-- MySQL      -> 127.0.0.1:3306
  +-- Redis      -> 127.0.0.1:6379
```

`star-web.top` 继续使用自己的站点目录和 Nginx 配置。支付域配置保持未激活状态，直到 DNS 指向新服务器且证书签发成功。

## 5. 实施设计

### 5.1 快照与回滚

变更前创建带时间戳的备份目录，保存：

- `/www/server/panel/vhost/nginx/mc-u.top.conf`
- `/www/server/panel/vhost/cert/mc-u.top/`
- `/www/wwwroot/mc-u.top/`
- `/www/wwwroot/qianfu-app/.env`
- PM2 进程清单和启动配置
- MySQL 逻辑备份

任何 Nginx 变更都先写入临时文件并执行 `nginx -t`。失败时不 reload。前端采用新目录部署并原子切换，保留上一版本用于快速回滚。

### 5.2 前端发布

前端在本地完成锁文件安装、类型检查和生产构建，避免在 3.5 GiB 服务器上高负载构建。上传完整 `dist`，校验清单和入口资源后，原子替换到：

`/www/wwwroot/qianfu-app/qianfu-liandeng/dist`

Nginx 主站根目录统一指向该路径。禁止只覆盖 `index.html`，避免入口与懒加载分片版本不一致。

### 5.3 Nginx 与 TLS

`mc-u.top` 使用独立的 80 和 443 server 块：

- 80 仅保留 ACME 验证并跳转到 HTTPS。
- 443 使用宝塔签发和续期的可信证书。
- `/api/`、`/auth/` 反代到 `127.0.0.1:3001`。
- SPA 路由使用 `try_files $uri $uri/ /index.html`。
- 哈希静态资源启用长期缓存，HTML 和 manifest 禁止长期缓存。
- 增加 HSTS、`nosniff`、Referrer Policy、合理的 Frame Policy 和基础 CSP。
- 保留上传大小、代理超时和真实客户端 IP 头。

只有证书签发成功且标准 TLS 校验通过后才启用 HSTS。

### 5.4 进程与启动管理

- `qianfu-api` 继续由 PM2 管理，工作目录固定为 `/www/wwwroot/qianfu-app`。
- 应用监听地址改为 `127.0.0.1`，端口保持 `3001`。
- 设置生产环境、内存上限、日志轮转和异常重启策略。
- 执行 `pm2 save` 并核对开机启动，不创建第二套重复的 Node 启动服务。
- Nginx、MySQL、Redis 使用宝塔实际安装对应的 init 管理入口；不再以错误的发行版 systemd 单元状态作为唯一判断依据。

### 5.5 数据库、缓存与内存

- MySQL 绑定 `127.0.0.1`，验证应用账户权限和数据库连通性。
- Redis 保持仅监听 `127.0.0.1`，关闭危险命令或设置认证，并验证应用降级策略。
- 创建 2 GiB Swap，设置保守的 `vm.swappiness`，避免构建或数据库峰值直接触发 OOM。
- 不在本轮执行数据库引擎迁移或 schema 重构。

### 5.6 网络与宝塔安全

主机防火墙和阿里云安全组仅公开：

- `80/tcp`
- `443/tcp`
- `22/tcp`，保留管理入口

关闭 `3001`、`3306`、`3452`、`8787`、`8788` 的公网入口，不停止其本地业务进程。宝塔 `27438` 暂时保留，完成登录验证后再配置入口限制、强认证和可信来源 IP，避免远程收口过程中失联。

### 5.7 备份与计划任务

- 每日执行 MySQL 逻辑备份，备份前验证数据库可连接。
- 每日备份保留 7 份，每周备份保留 4 份。
- 备份写入独立目录，不与应用发布目录混用。
- 每日执行本机健康检查、磁盘阈值检查和证书到期检查。
- 自动部署不采用每 15 分钟拉取并重启生产的模式；生产发布必须显式触发并通过验收门禁。

本轮只保证本机备份。异地备份需要单独提供对象存储桶或其他远端目标。

### 5.8 支付域

为 `pay.star-web.top` 准备独立 Nginx 配置和本地 upstream，但不安装到生效目录。切换必须满足：

1. DNS A 记录已指向 `121.196.161.249`。
2. DNS TTL 已收敛。
3. 新服务器可完成证书签发。
4. 支付回调来源、签名密钥和回调 URL 已核对。
5. 支付冒烟通过。

支付域切换不修改 `star-web.top` 主站内容。

## 6. 验收门槛

实施完成后必须同时满足：

- `nginx -t` 成功。
- `http://mc-u.top/*` 返回 301 到 HTTPS。
- 标准 TLS 客户端可以验证 `https://mc-u.top` 证书链。
- 首页、入口 JS、CSS、manifest 均返回正确内容类型和版本。
- `/api/health` 与 `/api/ready` 返回 200。
- 注册、登录和至少一个需要 API 的页面完成最小冒烟。
- PM2 进程稳定，无异常重启和新增错误日志。
- MySQL、Redis 仅能从本机访问。
- 公网无法连接 `3001`、`3306`、`3452`、`8787`、`8788`。
- Swap 已启用且重启配置持久化。
- 数据库备份可生成并通过基本恢复性检查。
- `star-web.top` 公网响应与变更前一致。

## 7. 非目标

- 不重装阿里云服务器或宝塔。
- 不修改 `star-web.top` 的站点文件或业务配置。
- 不在本轮切换 `pay.star-web.top` DNS。
- 不执行数据库 schema 重构、容器化或多机高可用改造。
- 不把任何密码、令牌或私钥写入仓库。
