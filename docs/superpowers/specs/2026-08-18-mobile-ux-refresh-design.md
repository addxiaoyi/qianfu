# 移动端全局体验优化设计

## 目标

让 320px 至 430px 宽度的移动端页面更容易扫描和操作：减少大留白与装饰性卡片，建立稳定的标题、正文、状态和操作层级，确保底部导航不遮挡内容，也不影响桌面端布局。

## 范围

- `MobileLayout`：顶部栏、滚动容器、安全区、底部导航和页面转场。
- `MobileBottomNav`：导航项尺寸、选中态、文字层级和触控区域。
- `MobileHome`：搜索入口、快捷操作、精选服务器卡片和加载/错误/空状态。
- `MobileSearch`：搜索栏、筛选/排序入口、结果卡片和空状态。
- `MobileServerDetail`：服务器封面、名称、地址、简介、发布者填写信息和操作区。
- 移动端公共样式：仅新增带移动端作用域的规则，不改变桌面端既有视觉。

## 设计原则

1. 以内容为主：服务器名称、简介、地址、平台、版本和QQ群按信息优先级展示；不生成接口没有返回的指标或文案。
2. 一览可见：首屏优先展示页面标题、关键操作和第一组真实内容，减少连续嵌套卡片。
3. 触控友好：主要按钮和导航项保持至少 44px 触控尺寸，图标按钮提供可读的 `aria-label`。
4. 字号克制：页面标题使用中等移动端字号，正文保持 14px 左右，辅助信息使用 12px，不默认使用全大写或过宽字距。
5. 状态完整：加载、失败、空结果、成功内容和操作反馈都必须有可见状态。
6. 动画收敛：只保留轻量的 opacity/transform 入场，尊重 `prefers-reduced-motion`，不让动画影响滚动和点击。

## 布局方案

### 页面壳层

`MobileLayout` 继续负责安全区和单一滚动容器。顶部栏固定高度并压缩上下留白；底部导航保持固定触控高度，内容区使用统一的底部内边距，避免最后一项被导航遮挡。页面转场只作用于内容容器，禁止横向位移造成视觉抖动。

### 首页

首页采用单列信息流：标题与搜索框作为首屏第一组内容，快捷入口改为紧凑的两列图标按钮，精选服务器使用横向稳定的缩略图、名称、简介摘要和在线状态布局。错误状态的重试按钮与错误说明保持同一操作组。

### 列表与搜索

搜索栏固定在结果区域顶部；筛选、排序和结果数量形成一个紧凑工具行。服务器结果使用统一列表卡片，卡片内最多展示真实的名称、简介摘要、地址或平台/版本信息，长文本截断只用于卡片摘要，详情页保留完整内容。

### 详情页

详情页按“名称与状态 → 地址操作 → 简介 → 发布者填写资料”的顺序排列。封面采用稳定宽高比，地址使用可换行的等宽文本并提供复制按钮，简介使用真实 `content_html`，没有简介时显示明确空状态。平台、版本、QQ群等字段使用两列信息行，避免大面积空白。

## 数据与组件边界

- 继续复用 `serverView` 中的名称、简介、平台、版本、状态和封面解析函数。
- 移动端组件只负责展示和交互，不在组件内创建默认服务器数据。
- 过滤和排序继续通过现有 API 请求与 `MobileSelectSheet` 完成。
- 不在本次改造中修改后端数据模型、权限、DNS、邮件或桌面端页面。

## 验收标准

- 320px、375px、430px 宽度下无横向滚动和文本覆盖。
- 首页、服务器列表、搜索、详情和底部导航均能完成主要点击流程。
- 刷新、加载失败、空结果和无封面状态可见且可操作。
- 服务器简介显示真实发布内容，不显示名称替代简介或虚构指标。
- `prefers-reduced-motion` 下无明显位移动画。
- 移动端相关单元/契约测试通过，生产构建通过；部署后用真实移动视口检查首页、列表和详情页。
