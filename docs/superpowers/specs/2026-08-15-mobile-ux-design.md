# 移动端核心路径 UX 强化设计

## 目标

强化窄屏设备上的首页、服务器发现、服务器详情、服务器发布和个人中心体验。保留现有路由、权限、请求接口、URL 查询参数和桌面端布局，只调整移动端壳层与移动专用组件的信息层级、触控操作和安全区行为。

## 约束

- 移动端由 `App.tsx` 的窄屏路由分支进入，不改变桌面路由。
- `MobileLayout` 继续作为共享滚动根节点，负责安全区、顶栏、页面过渡和底部导航。
- 选择控件不使用原生 `<select>`，改为可访问的自定义菜单或底部抽屉。
- 任何可触控操作至少保持 44px 命中区域。
- 外部接口和数据结构不变；失败数据不能被静默替换为 0。

## 页面设计

### 共享移动端壳

根页面保留 `首页 / 发现 / 发布 / 消息 / 我的` 底部导航。详情、发布、工单等任务页显示返回型顶栏，并把主操作放进带底部安全区的固定操作栏。内容区域只保留一个滚动根节点，避免浏览器窗口和内层容器同时滚动。

共享壳统一处理顶部安全区、底部安全区、键盘可见时的可用高度，以及加载、过渡和刷新状态。页面组件只声明自己的标题、返回行为和主操作。

### 发现页

首屏顺序为搜索、分类、意图快捷项、结果列表。搜索状态继续写入 URL，键盘 Enter 提交，清除操作保留。平台、版本、在线状态和排序集中在筛选底部抽屉，入口显示已应用筛选数量。

结果卡片使用紧凑的图像、名称、摘要、版本、在线状态和在线人数信息，并提供详情链接与复制地址按钮。请求失败显示重试；无结果时提供清除筛选和发布入口。加载状态使用稳定尺寸的骨架，避免列表跳动。

### 首页

首屏直接展示搜索和找服、发布、工单等主要入口，精选服务器提前进入第一屏。减少装饰性留白，保留当前数据请求和失败重试状态。精选卡片与发现页使用一致的服务器摘要信息和状态表达。

### 服务器详情

顶部显示服务器名称、缩略图和在线状态；连接信息、介绍和标签分组展示。复制地址、收藏和进入门户等主操作放在底部安全区操作栏，内容滚动时保持可达。主服务器请求失败时不启动依赖服务器数据的请求，并提供明确的重试或返回入口。

### 服务器发布

表单按基础信息、连接信息、展示信息和域名配置分组。顶部显示当前分组和草稿状态；底部固定保存草稿与提交审核操作，使用键盘安全区避免遮挡输入内容。校验错误定位到对应字段，提交中禁用重复操作，保持已有免费域名和审核流程。

### 个人中心

账户身份、等级和核心统计进入首屏。服务器、工单、签到等统计继续区分加载、失败和空值。我的服务与账户设置采用 44px 高度的操作行；访客显示只读状态和登录入口，已登录用户保留退出登录操作。

## 交互与可访问性

- 所有自定义菜单提供按钮语义、展开状态、关闭操作和键盘可用性。
- 底部抽屉打开后锁定背景滚动，关闭后恢复触发控件焦点。
- 复制地址反馈同时通过 toast 和按钮状态变化提供确认。
- 页面提供空数据、失败、重试和提交中状态；不可用操作明确 disabled 或 aria-disabled。
- 不新增视觉动画依赖，沿用现有过渡能力并优先保证低端设备滚动稳定。

## 验证

- 运行移动端发现、详情、查询状态、服务器列表和现有前端契约测试。
- 在 375px、390px、768px 宽度验证首屏、横向溢出、触控区域、底部安全区和键盘避让。
- 检查发现页筛选状态刷新后仍由 URL 恢复，复制地址不触发详情跳转，详情和发布页主操作不被底部导航或系统手势区遮挡。
- 构建前端并确认未引入原生下拉框、API 密钥或凭证回显。

## 非目标

- 不重写后端 DNS、邮件、AI 或审核逻辑。
- 不改变桌面端布局和桌面端数据接口。
- 不清理工作区内与本设计无关的既有改动。
