# 优化项 108: Redis 缓存策略 - 多级缓存

## 概述

本优化项实现了多级缓存架构，显著提升缓存命中率和系统响应速度。

## 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                        请求入口                               │
└─────────────────────┬───────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                    L1: Process Memory                        │
│  - 进程内缓存，最快 (< 0.1ms)                                │
│  - 最大 500 条目                                            │
│  - 默认 TTL: 30 秒                                          │
│  - 智能 LRU 淘汰                                             │
└─────────────────────┬───────────────────────────────────────┘
                      │ Miss
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                    L2: Local LRU Cache                       │
│  - 实例级缓存，较快 (< 1ms)                                  │
│  - 最大 2000 条目                                           │
│  - 默认 TTL: 5 分钟                                         │
│  - 访问频率追踪                                              │
└─────────────────────┬───────────────────────────────────────┘
                      │ Miss
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                    L3: Redis (Distributed)                   │
│  - 分布式缓存，中等延迟 (~5-20ms)                             │
│  - 持久化，支持多实例共享                                      │
│  - 默认 TTL: 1 小时                                         │
│  - 连接故障自动降级                                           │
└─────────────────────┬───────────────────────────────────────┘
                      │ Miss
                      ▼
┌─────────────────────────────────────────────────────────────┐
│                       数据源                                  │
│                    (Database)                                │
└─────────────────────────────────────────────────────────────┘
```

## 核心特性

### 1. 三级缓存
- **L1 (Process Memory)**: 最快，用于高频访问数据
- **L2 (Local LRU)**: 中等，平衡速度和容量
- **L3 (Redis)**: 分布式共享，保证多实例一致性

### 2. 智能 TTL 配置
```javascript
// 默认配置
const DEFAULT_CONFIG = {
  l1MaxSize: 500,           // L1 最大条目
  l1DefaultTTL: 30_000,     // L1 TTL: 30秒
  l2MaxSize: 2000,          // L2 最大条目
  l2DefaultTTL: 300_000,    // L2 TTL: 5分钟
  redisTTL: 3600,            // Redis TTL: 1小时
  redisKeyPrefix: 'mlc:',   // 缓存键前缀
};
```

### 3. 缓存预热
预热脚本在系统启动时填充高频数据：
- 全局统计数据 (L1: 30s, L2: 5min)
- 服务器列表 (L1: 10s, L2: 1min)
- 热门标签

### 4. 监控指标
```javascript
{
  hits: { l1: 850, l2: 120, l3: 20, miss: 10 },
  rates: { l1: 85.0%, l2: 12.0%, l3: 2.0%, miss: 1.0% },
  l1: { size: 500, maxSize: 500, memoryBytes: 2_500_000 },
  l2: { size: 2000, maxSize: 2000, totalHits: 140 },
}
```

## 使用示例

### 基本用法
```javascript
import { multiLevelCache } from './services/multiLevelCache.js';

// 设置缓存
await multiLevelCache.set('user:123', userData, {
  l1TTL: 10_000,    // 10秒
  l2TTL: 60_000,    // 1分钟
  redisTTL: 3600,    // 1小时
});

// 获取缓存
const user = await multiLevelCache.get('user:123');

// 删除缓存
await multiLevelCache.delete('user:123');
```

### 带回源的缓存获取
```javascript
const user = await multiLevelCache.getOrFetch(
  'user:123',
  () => prisma.user.findUnique({ where: { id: '123' } }),
  { ttl: 3600, staleTime: 60000 }
);
```

### 便利函数
```javascript
import { cacheGet, cacheSet, withCache } from './services/multiLevelCache.js';

// 简单获取/设置
const data = await cacheGet('key');
await cacheSet('key', data, 3600);

// 带回源
const data = await withCache('key', async () => {
  return await fetchFromDB();
}, { ttl: 300 });
```

## 性能对比

| 场景 | 单级 Redis | 多级缓存 |
|------|-----------|---------|
| 首次访问 | ~15ms | ~15ms |
| L1 命中 | N/A | < 0.1ms |
| L2 命中 | N/A | ~1ms |
| Redis 命中 | ~15ms | ~1ms |
| L1 命中率目标 | 0% | 70-85% |
| 平均响应时间 | ~15ms | ~2ms |

## 降级策略

1. **Redis 不可用**: 自动降级到 L1 + L2
2. **内存不足**: 自动触发 LRU 淘汰
3. **获取失败**: 返回 null，触发回源

## 注意事项

1. **数据一致性**: 多级缓存可能导致短暂的数据不一致，使用 `delete()` 清除缓存
2. **内存限制**: L1 缓存有内存限制 (~10MB)，大对象请谨慎使用
3. **TTL 配置**: 根据数据更新频率调整 TTL
4. **分布式部署**: 多实例部署时，修改 L3 (Redis) 数据后需主动清除缓存
